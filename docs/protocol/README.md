# Frozen analytical design, version 1

> This document describes the earlier respondent-day benchmark. The current article uses the [whole-meal profile study](../profiles/README.md).

This document and `design.json` specify the confirmatory comparison before any optimization run. `run-matrix.csv` enumerates planned work; it contains no performance results. The source and cohort validations are in `../validations/`. Changes to this design require a dated decision record and a new study ID before the affected runs.

## Inputs and analytical cohort

Use the official POF 2017–2018 July 2023 data and documentation archives and the November 2023 Brazilian environmental workbook at the URLs and SHA-256 checksums in [the data validation](../data-validation.md). The environmental workbook remains a local input because its OSF record does not state a redistribution license. The POF microdata and all derived nutrient coefficients also stay local.

Join each six-part consumption person-day key to the five-part `MORADOR` respondent key. Eligible days belong to adults aged 19–59 with sex code 1 or 2, have only occasion codes 1–6, at least two distinct occasions, at least five food/preparation/occasion variables, positive reported energy, and strictly positive carbon and water coefficients for every *optimized* line. A blank preparation on an addition line uses workbook preparation 99 only if that food has exactly one preparation row and it is 99. No fuzzy link is permitted. Public tap water (`8216301#99`) is held at its observed mass and omitted from the decision vector. Its workbook zero footprints are assigned/unpublished, not measured zeros, so no environmental improvement is attributed to changing its amount. Its reported nutrient contribution, including sodium, is retained as a fixed term.

Select the first eligible day in code order for each respondent. From each age band (19–39, 40–59) by sex-code stratum, retain the six respondents with the lowest SHA-256 rank of `sec2026-benchmark-v1|` followed by the six raw identity fields separated by `|`. Publish only opaque day hashes. This yields 24 independent respondent-day benchmark instances, six in each stratum. This is a deliberately balanced algorithm benchmark, not a probability sample for Brazilian prevalence estimates; no survey weights are used in the algorithm comparison.

For a POF food/preparation key (i), estimate the per-gram coefficient of energy, fiber and sodium separately from all records of this source release: (a_{ik}=\sum_r g_r y_{rk}/\sum_r g_r^2), where (g_r) is recorded grams and (y_{rk}) is its absolute reported nutrient amount. Duplicate lines of the same food/preparation/occasion on a selected day are summed into one baseline variable. Keep a blank preparation distinct for nutrient estimation; its conditional 99 mapping applies only to environmental linkage. Every source record has numeric values for these three nutrients, the within-key per-100-g diagnostic found no keys with a difference above 5% or zero/positive disagreement, and no food/preparation key had multiple TBCA identifiers. This supports computational consistency within the POF release, not independent validity of the underlying TBCA composition. No restricted TBCA table or derived coefficients are published.

## Optimization problem

For variable (j), let (b_j>0) be observed grams of its food/preparation/occasion combination and (x_j) its candidate grams. The food universe and occasion assignment are fixed to the observed day: (0\le x_j\le 2b_j). Foods cannot be introduced or moved to a new occasion in this comparison. If (t_k) is the fixed nutrient amount from observed tap water, daily modeled intake is (q_k(x)=t_k+\sum_j a_{jk}x_j). The baseline energy is (E_b=q_E(b)>0), and the sole non-box constraint is (0.8E_b\le q_E(x)\le1.2E_b). Thus the observed baseline is feasible by construction. This energy band is a computational control, not a personalized nutritional recommendation. Fiber and sodium are aspirations, not hard constraints.

The four raw minimization objectives are:

* (N(x)=\tfrac12[\max(0,25-q_F(x))/25+\max(0,q_{Na}(x)-2000)/2000]), with fiber in g/day and sodium in mg/day. These population-level reference values come from the [WHO healthy diet information sheet](https://www.who.int/docs/default-source/healthy-diet/who-nmh-nhd-18-12-eng.pdf) and are not individual prescriptions.
* (C(x)=\sum_j c_jx_j), where (c_j) is workbook g CO2e/100 g divided by 100, giving g CO2e/day.
* (W(x)=\sum_j w_jx_j), where (w_j) is workbook L/100 g divided by 100, giving L/day.
* (D(x)=\sum_j|x_j-b_j|/\sum_j b_j), excluding the fixed tap-water mass.

Every coefficient of an optimized line must be finite and nonnegative; carbon and water must additionally be strictly positive. Abort preparation if an expected coefficient or source hash is absent or different. Report all four raw outcomes for every evaluated diet, including dimensions omitted from the current objective subset. The ten subsets are `N,C`, `N,W`, `N,D`, `C,W`, `C,D`, `W,D`, `N,C,W`, `N,C,D`, `N,W,D`, and `C,W,D`. A diet is feasible only when it satisfies the box and energy constraints within the implementation's documented numerical tolerance. Pareto dominance uses only the chosen subset among feasible diets.

For algorithm fitness and quality metrics, normalize using fixed mathematical bounds from the instance, before seeing optimizer results. Let (N_{\max}=\max\{1,\tfrac12[1+\max(0,t_{Na}+2\sum_j a_{j,Na}b_j-2000)/2000]\}\), (C_b=C(b)>0), and (W_b=W(b)>0). Then use (N/N_{\max}), (C/(2C_b)), (W/(2W_b)), and (D). These lie in [0,1] under the box bounds and nonnegative coefficients. Keep the raw objective values in the outputs. The external hypervolume reference point is `(1.1, …, 1.1)` in the selected normalized dimensions. It is distinct from any reference point internal to SMS-EMOA survival.

## Algorithms, evaluation limit, and outputs

Compare NSGA-II, SPEA2, NSGA-III, and SMS-EMOA as implemented in `pymoo` 0.6.1.6, which is [Apache-2.0 licensed](https://github.com/anyoptimization/pymoo/blob/0.6.1.6/LICENSE). The [software paper](https://doi.org/10.1109/ACCESS.2020.2990567) documents the framework. Pin NumPy 2.4.1 and SciPy 1.17.0 as in `requirements-experiment.lock`. Use population 66, 66 offspring per generation for NSGA-II, SPEA2 and NSGA-III, and one offspring per step for SMS-EMOA. NSGA-III uses Das–Dennis reference directions with 65 partitions for two dimensions and 10 for three, giving 66 directions in either case. All algorithms in the same instance/subset/replicate start from the same 66 vectors: observed baseline and 65 uniform random points within the box. Use SBX crossover with probability 0.9 and eta 20, polynomial mutation with per-variable probability (1/n) and eta 20, and duplicate elimination. Use the framework's feasibility-first constraint handling; apply no custom penalty or repair. This is a comparison of complete configurations, including different survival mechanisms and offspring scheduling.

Each run has 1,650 objective evaluations including initial solutions, a 900 s wall-time cap and a single-threaded objective evaluator. Schedule at most eight runs concurrently. Plan 20 replicates numbered 1–20 per instance/subset/algorithm. The first 32 bits of SHA-256 of `sec2026-pof-person-day-v1|person_day_id|objective_subset|replicate_id` are the common seed across algorithms; replace zero by one. The matrix has 24 × 10 × 4 × 20 = 19,200 rows and 31,680,000 planned objective evaluations. A time cap or error ends a run early; preserve partial solutions and the stopping reason. Never relabel a partial run as complete or replace its seed.

Each future run must save `config.json`, `evaluated-solutions.jsonl`, `final-population.jsonl`, `front.jsonl`, `metrics.json`, `resources.json`, and `run.log` under its matrix run ID. Save every evaluated solution and the complete final population/archive, with raw and normalized objectives, constraint violation, feasibility, evaluation ordinal and source hashes. Derive the reported front from **all feasible evaluated solutions**, retaining unique nondominated diets. The run metadata must include code revision, package versions, effective parameters, seed, actual evaluations, wall/CPU time, peak memory, and stop reason. These are output requirements for the implementation phase, not files already produced.

## Registered analysis

The primary endpoint is external hypervolume of the feasible nondominated evaluated set, using the fixed normalized reference point. The empty set has hypervolume zero. A partial run contributes only its actual stopped front, and its incomplete status remains explicit. For each respondent-day, subset and algorithm, take the median across the 20 planned seed outcomes. There are six unordered algorithm contrasts within each of ten subsets: 60 primary comparisons. Estimate the mean of the 24 paired respondent-level differences, a 95% percentile interval from 9,999 respondent bootstrap resamples, and a two-sided paired sign-flip Monte Carlo p-value from 99,999 sign vectors. Apply Holm adjustment across all 60 p-values at 0.05. Use fixed random seeds and publish the random generator for resampling when implemented. Report effect sizes and intervals even when tests are inconclusive. Missing run artifacts are reported as missing and never silently replaced; sensitivity bounds will show their possible impact.

Secondary analyses describe IGD+ against the pooled feasible nondominated reference set within each instance/subset; a leave-one-algorithm-out reference sensitivity addresses self-inclusion. If no pooled reference exists, IGD+ is undefined and reported as missing. Also report completion, feasibility, unique set size, runtime, CPU time, peak memory, raw diet outcomes, and algorithm rank stability across two versus three dimensions. Compare ranks and diet outcomes across dimensions; do not subtract raw hypervolumes from spaces of different dimension. Summaries by age and sex are exploratory, with six selected respondents per stratum. No confirmatory optimization results existed when this design was frozen.
