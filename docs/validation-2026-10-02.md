# Software validation, 2 October 2026

Scope: phase 5 implementation. These checks use either artificial five-variable diets or the two previously checked local POF/environmental inputs for instance reconstruction. No registered optimizer run or confirmatory result was produced.

1. The five controlled tests passed in the development checkout. They cover baseline energy/fiber/sodium arithmetic, fixed tap-water sodium, carbon and water units, energy feasibility, Pareto dominance, an analytical two-dimensional hypervolume, all four `pymoo` adapters, exact evaluation limits, independent rescoring of every saved diet, repeated-seed byte identity, detection of a corrupted or missing front, and a complete CLI run/check cycle with a one-row artificial matrix.
2. The official POF and environmental workbook passed the frozen SHA-256 checks. The local builder reconstructed all 24 selected person-day instances, checked their expected variable counts (5–19) and baseline feasibility, and wrote a local instance manifest. These derived instance files are ignored by Git and were not published.
3. A fresh local clone of the phase 5 implementation was installed in a new virtual environment with `pip install -e ".[experiment]"`. The controlled tests passed there. The same fresh clone reconstructed all 24 local instances from the original input archives without importing from the parent project.
4. `sec-build-instances`, `sec-run`, and `sec-check-results` registered as console commands and displayed their command-line interfaces. The documented full-matrix command requires `--all`; an individual run requires an explicit registered ID. The result checker reports incomplete, missing and invalid artifacts separately and exits nonzero unless every requested run is complete.

The checks establish that the implementation is installable and that the controlled full path produces reproducible artifacts. They do not estimate runtime or resource use for the full 19,200-run workload. The limited real-input integration pilot and the confirmatory matrix remain in roadmap phase 6. Peak memory currently measures Python-traced allocations; native allocations are excluded and labeled as such in `resources.json`.
